SCS 多系统协同

本项目演示多个SCS单元在一个架构中的协同工作。包含两个独立系统：

User SCS (用户SCS)

独立的系统单元，管理用户注册、查询、状态管理

  • 路径: /user-scs/
  • API: /user-scs/api/v1/users
  • 数据库: USER_SCS_DB
  • 发布事件: UserCreated, UserDeleted
进入 User SCS

Order SCS (订单SCS)

独立的系统单元，管理订单创建、查询、关联

  • 路径: /order-scs/
  • API: /order-scs/api/v1/orders
  • 数据库: ORDER_SCS_DB
  • 监听: UserCreated事件
进入 Order SCS

SCS 核心设计原则

数据隔离

每个SCS有独立数据库。User SCS的USER_SCS_DB和Order SCS的ORDER_SCS_DB完全隔离。

异步通信

服务间通过事件通信，而非同步HTTP。发布事件后不等待处理结果。

前端自包含

每个SCS有自己的前端UI，在不同路径前缀下提供服务。

独立部署能力

虽然这里在同一个jar中演示，但每个SCS可以独立打包为jar部署。
